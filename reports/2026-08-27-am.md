## 물어오리 릴스 (daily-news-reels) — am 회차
- 마커: `published/2026-08-27-am` = `17887652292654897` (media id) → **발행 성공**
- 파이프라인: `reels: 2026-08-27-am`(22:21 UTC) → `reels build`(22:27) → `reels publish`(22:31) → `metrics`(22:46) — 전 단계 정상 완주
- `data/`, `containers/` 등 생성 루틴도 정상 실행된 것으로 확인

## AI뉴스 카드뉴스 (briefing-cards) — 아침 1회 발행
- **마커 없음**: `published/2026-08-27`, `cards/2026-08-27` 모두 미생성 (렌더조차 시작 안 됨)
- `digest/2026-08-27` (actions-relay) 마커만 존재 — 06:53 KST에 브리핑→카드뉴스 트리거 릴레이까지는 도달
- **원인**: daily-briefing 리포의 `cardnews.yml` 워크플로우(cron `20 22 * * *` = 07:20 KST)가 오늘 **전혀 실행되지 않음**. Actions API 조회 결과 가장 최근 run은 8/26 회차(07:48 KST 실행)이며, 오늘자 run은 완료/대기/진행 중 어느 상태로도 존재하지 않음(큐잉·in_progress 0건). GitHub Actions 스케줄 트리거 자체가 발화하지 않은 것으로 판단됨.
- `watchdog-cardnews`(cron 08:30 KST, 미게시 감지 시 텔레그램 경보)도 현재(08:52 KST) 기준 오늘자 실행 이력 없음 — 경보 자체가 아직 발송되지 않은 상태.
- 데이터 문제 아님: `briefings/2026-08-27.md`는 정상 생성·헤더 날짜 일치 확인 — cardnews 게이트는 통과 가능한 상태였음. 즉 콘텐츠 부재가 아니라 **워크플로우 미발화**가 원인.
- **거짓 403 지속/해소**: 직전 확인 가능한 8/26 회차 로그(`publish.mjs`)에서는 media_publish 이후 재시도 없이 바로 "게시 완료"로 이어짐 → **최소 8/26 기준 거짓 403 미재현**. 오늘(8/27)은 워크플로우 자체가 안 돌아 확인 불가.

## daily-briefing
- `collect: 2026-08-27 raw sources`(07:22 KST), `briefing: 2026-08-27`(06:50 KST), `briefing: 2026-08-27 (telegram-failed)`(06:53 KST, 2분 뒤 재커밋) — 브리핑 본문 자체는 정상 생성됨
- `(telegram-failed)`는 브리핑 텔레그램 전송 실패 흔적으로 발행 파이프라인과 무관

## 권장 조치 (사람이 할 일)
1. `cardnews.yml` 수동 트리거: `gh workflow run cardnews.yml -R calintzy/daily-briefing -f dry_run=0` (watchdog.yml에 명시된 복구 명령과 동일)
2. daily-briefing 리포 Settings → Actions에서 스케줄 워크플로우 활성화 상태 확인 (비활성화/일시정지 여부)
3. 수동 트리거로도 안 되면 GitHub Actions 스케줄러 자체의 지연/장애 가능성 — 잠시 후 재확인
